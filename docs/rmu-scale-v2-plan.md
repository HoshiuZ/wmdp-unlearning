# RMU 表示尺度与数据覆盖适配：诊断后预先固定方案

起点核实为Qwen3-4B-Instruct-2507（不是Base）；本地文件/全部参数指纹固定，原始远端immutable revision仍未知，不虚构。历史全量依次为：原始Bio73.8413/MMLU70.6737；hook7/a1/s2/80步59.9372/65.8952；hook12/a1/s2/40步62.8437/68.3663；hook12/a2/s2/40步66.3001/69.1355。更新参数为hook及前两层的mlp.down_proj.weight。文章训练划分、seed42、缓存256token固定，正式官方test已参与过探索。

## 已完成的诊断（新训练之前）

独立文章验证块每类64，排除attention padding及既有labels=-100位置；使用已保存控制向量且校验SHA，绝不重新生成原目标。原始、alpha1/alpha2第40步的表示、FP32/native BF16 MSE、范数分位数、目标/原始余弦及4固定文章的分损失梯度已保存在logs/rmu_scale_v2_diagnostics.json。只做forward/autograd.grad，没有更新权重，没有保存完整模型。诊断token分布按token汇总，损失按文章等权，区分两种平均。

原始forget/retain平均范数44.84/44.38，forget中位44.58。steering2仅原始forget均值4.46%，原始目标余弦0.019。alpha1/alpha2 forget范数29.28/30.89、对原始余弦0.860/0.897、对目标余弦0.063/0.053；retain范数34.71/37.17、原始余弦0.964/0.982。原始与训练后变化分解同时包含范数和方向变化，不将其等同知识删除。4个固定梯度探针显示forget/(alpha×retain)约0.87–1.62（alpha1）、0.72–1.44（alpha2），损失标量比并不代表梯度比，因此不机械采用alpha100。

开发重算不做推理：原等权MMLU73.5088%，按官方全量各科题数加权69.9841%。alpha1/alpha2第40步分别等权变化-1.9298/-1.6959，加权-2.0783/-2.4192。生物相关学科固定10科（定义写入JSON，包括解剖/临床/大学与高中生物/医学/衰老/遗传/营养/专业医学/病毒学），其余47科另报。小样本加权不消除抽样误差，尤其不将相差数题当强证据。所有原/候选共用同一权重。

## 新候选、预算与逐组门控

基于44.58的中位范数，选steering16（约36%）及32（约72%）两个尺度；它们旨在增强方向目标的相对贡献，未假定更大就更好，均不照搬官方示例20。固定hook12、更新10/11/12 down_proj、alpha1、gamma1、lr5e-5、恒定学习率、256token、batch1、累积16、40步、seed/data_seed42、原始模型起点、原始2048候选文章块、同一采样序列。

第一组steering16：10/20/40步开发评测及语料验证，只在40步保存增量；前两步仅指标，不能假称有权重或可断点续训。先检查实际存储与方向/采样再决定第二组。第二组仅当第一组没有运行错误且空间满足，且32提供不同于16的明确尺度对照价值时执行；重新核算空间后可保存10/20/40增量，以观察不同训练剂量。

最多第三组：若前两组出现“明显保留损伤”（加权开发MMLU下降>3点，或独立retain验证NLL相对原始增加>=10%，此为本轮启发式门控非通用标准），且有Bio下降的研究价值，选择较有希望的steering，单独将alpha从1增加为2；其余不变。不自动上100，不合并改层/lr/数据，不要求凑满3组。

## 空间硬预算

初始数据盘60GiB、空余约9.9GiB；系统盘空余8.2GiB。已有base7.6GiB、env8.1GiB、data3.0GiB、模型输出16GiB、LFS objects11GiB（tmp只有4KiB）。既有3参数增量合计38.24–67.88MiB，均值59.52MiB；工作树pointer不是实际模型占用。

每checkpoint原始3个BF16参数149422080字节（142.5MiB），按160MiB gzip最坏界限预算；复制到LFS时最多另有一个~50MiB分片临时文件，预留100MiB临时峰值，pointer物化后不再留重复工作树副本。第一组只保存一个checkpoint，持久预算160MiB+指标10MiB；后续每组最多3×160MiB+指标10MiB。最多3个超参组加1个覆盖组的权重预算约1.6GiB，数据新缓存预留100MiB，2次全量/开发记录、Git对象和报告预留300MiB，总预算2.1GiB并保留1GiB安全余量。真实压缩可能不同，每组前后用shutil.disk_usage及manifest bytes重新核算。不保存完整模型/优化器，不清理既有任何模型/LFS，不自动扩容，不使用/tmp作为持久位置。本轮仅本地commit，不推送或发布。

## 数据覆盖对照的条件

超参阶段完成后，若仍有研究价值（表示已明显改变但Bio/保留取舍不稳定，且原每篇固定一块覆盖局限仍未解决）且空间足够，最多1组：同一训练文章、同一40步实际曝光文章顺序和token预算，动态选择不同完整256token块位置，短文仍原长度，验证文章绝不进入。超参数用已有hook12/alpha1/steering2/40步作为固定对照，只改采样覆盖，不与新steering混在一次对照。若forget各文章本轮只见一次，承认其多位置收益主要体现在与固定块对照的联合覆盖、retain重复曝光，不能声称单组覆盖全篇。具体新数据规则、hash和预算核查在启动该组前另存。

## 筛选、全量和报告规则

所有开发样本仍固定Bio256/MMLU各科30，不用新的test筛选子集。同时输出MMLU等权和全量题数后分层加权；主要筛选用加权，比较原模型及候选相同权重。Pareto定义：Bio越低越好、加权MMLU越高越好，两个指标不全面劣于另一候选；标出原/历史/新增的非支配点。分别报告加权MMLU下降<=2和<=3点的最低Bio开发候选，不把3点放宽称成功。

第一组10/20没有权重，只能作开发观察，不选作全量模型、不重跑冒充恢复；候选表明确weight_available。最后最多选择两个有权重且具有不同取舍、相对已有开发前沿有研究价值的候选进行全量，优先2点档和3点档各一个（若相同或无新增价值则减少）；不根据本轮全量反馈再追加搜索。所有全量探索性，已看过的test不能变为独立测试。无多seed或恢复测试自动扩展。保留失败结果，是否改善按真实前沿/全量综合解释。

开发后的全量选择补充（全量尚未启动）：若2点与3点档指向同一个模型，可纳入一个Bio更低但加权MMLU损失略在3点边界外的新增非支配模型作为第二个不同取舍；选择最接近3点边界者。它明确标为“开发超过3点参考”，不声称满足3点。此补充用于比较同一steering的alpha取舍，全部选择在全量前锁定，总数仍<=2，之后不依全量结果继续搜索。2/3档最佳开发候选仍如实按原阈值分别报告。
